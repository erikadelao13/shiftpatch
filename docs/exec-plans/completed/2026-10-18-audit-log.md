# Audit log on real events

Status: Completed
Owner: current agent
Created: 2026-10-18

## Goal and acceptance criteria

The admin audit log at `/admin/audit` shows real `AuditEvent` rows instead of the mockup's sample events, and posting a shift is audited, so PR-11 holds: successful post, claim and cancel changes (and credential saves) appear as truthful events, and failed attempts do not appear.

Acceptance:

1. `createShift` writes the shift and exactly one `shift_posted` audit event in one transaction. A refused post (nurse, admin, invalid input) writes neither.
2. `/admin/audit` lists the newest 50 `AuditEvent` rows, newest first. The header shows the total count, and the footer reads "Showing 50 of N events" when rows are cut off and "Showing N events" otherwise. The existing empty state stays.
3. Each action renders with the label and details in DESIGN §7's audit table. The Actor column shows the real name and role. The Record column shows the shift ID for shift events and the nurse ID for credential events.
4. `src/features/audit/sample-events.ts` is deleted and nothing imports it.
5. Only the admin can open the page (existing `requireRole("admin")`). There is no new API route.
6. Unit, integration and e2e tests below pass. After a run the dev branch still holds 0 `AuditEvent` rows.
7. ARCHITECTURE, DESIGN, VERIFICATION, decisions and the tech-debt tracker match the result. TD-15 and TD-17 are removed. `pnpm verify` passes.

Non-goals: filters, search, paging past 50, export, auditing logins or failed attempts, retention or pruning, events backfilled for seeded shifts, seeded audit rows, an audit JSON API.

## Context

- **Already built and uncommitted on `main`:** the audit UI on sample events (`src/app/(workspace)/admin/audit/`, `src/features/audit/{types,describe-event,sample-events}.ts`, `components/audit-log*.tsx`), the sidebar `SidebarNav`, four icons, the `info` color tokens, the e2e audit specs in `e2e/admin-ui.spec.ts`, and the docs for these. `AuditEntry` (`src/features/audit/types.ts`) is the UI's shape; `describeAuditEvent` turns it into labels.
- **Writers today** (`recordAuditEvent` in `src/features/audit/server/audit-service.ts`, transaction client only):
  - `claimShift` writes `shift_claimed` with `{ agencyId }`.
  - `cancelShift` writes `shift_cancelled` with `{ agencyId, reason, previousNurseId }`, where `reason` is `"advance"` or `"no-show"`.
  - `saveCredential` writes `credential_updated` with `{ previousExpiresOn, expiresOn }`, and `resourceId` is the `Credential` UUID.
  - `createShift` (`src/features/shifts/server/shift-service.ts:68`) writes no audit event and runs no transaction.
- **Schema:** `AuditEvent` (`prisma/schema.prisma:136`) has `actorId` as a RESTRICT foreign key, an `AuditAction` enum without `shift_posted`, JSON `metadata`, and an index on `createdAt`.
- **Pattern to copy:** the admin overview page (`src/app/(workspace)/admin/page.tsx`) authorizes with `requireRole("admin")` inside `<Suspense>` and calls a service with no actor. `shift-presenter.ts` and its test show the presenter layout.
- **Trap:** `tests/integration/shifts.test.ts:25` posts as `test-<run>-user`, which has **no `User` row**. Once posts are audited, the actor foreign key rejects that insert. The test must create the user and delete its audit rows before deleting it.
- e2e cleanup (`deleteOwnRows` in `e2e/support.ts`) already deletes audit rows by the IDs of shifts the specs created. Playwright runs `fullyParallel`, so other specs' events can appear in the table at the same time.

## Decisions and discoveries

Owner decisions (2026-10-18, while planning):

- **Page only, no `GET /api/admin/audit`.** The page's `requireRole("admin")` authorizes, as on the admin overview.
- **The newest 50 events plus a total count.** There are no paging controls.
- **Credential events show the nurse ID** in the Record column. New events store `nurseId` in their metadata, and older rows fall back to the actor.

Agent defaults, not yet reviewed by the owner:

- `shift_posted` metadata is `{ agencyId, role, date }`, a snapshot taken at post time.
- Metadata is parsed strictly. A malformed row fails the page instead of being dropped, because hiding history is worse than a visible error. The integration test proves that each writer's metadata parses.
- Only successful business events are audited. There are no login or failed-attempt events, no backfill for seeded shifts and no seeded audit rows, so the dev page shows the empty state until someone acts.
- The existing UI work is committed on `feat/audit-log` before the data change.
