# Tech debt tracker

Known, accepted, nonblocking gaps. Each entry names the impact and a concrete follow-up. Delete an entry when it is resolved; promote it to a plan when it starts blocking work.

| # | Gap | Impact | Follow-up |
| --- | --- | --- | --- |
| TD-1 | Every feature has Vitest unit and integration tests and Playwright specs, but there is no component-level testing (Testing Library), and no automated test runs against the production deployment. | Component states are reached only through the e2e specs, and a production regression is caught only by the manual smoke check in [../VERIFICATION.md](../VERIFICATION.md). | Each feature plan adds its own tests. Add Testing Library when the first non-trivial interactive component beyond the login form exists. |
| TD-6 | `pnpm-workspace.yaml` exists with no `packages` key, carrying only `ignoredBuiltDependencies` and `onlyBuiltDependencies` (Prisma, its engines, and esbuild). | Suggests a monorepo that does not exist; may confuse tooling. | Leave as-is while it is load-bearing for pnpm; remove if those entries become unnecessary. |
| TD-7 | The shell's default Node is 18.17.1, below the `>=20.9.0` Next.js 16 requires. Since 2026-10-16 the Git hooks and Claude Code sessions select the `.nvmrc` version from nvm, and `engine-strict=true` makes every `pnpm` command fail immediately on the wrong Node. | An interactive shell still needs `nvm use` before any `pnpm` command, and the automatic pin covers nvm only. | Make Node 20+ the shell default (`nvm alias default 24.16.0`) if no other project needs 18, or enable nvm's `.nvmrc` auto-switching in the shell profile. |
| TD-8 | `pnpm typecheck` depends on `.next/types/`, generated by a build. `.githooks/pre-commit` therefore skips it on a never-built tree. | A fresh clone gets weaker pre-commit coverage than the hook's output suggests. | Revisit if Next.js 16 gains a standalone typegen command; until then `pnpm verify` builds first and covers it. |
| TD-9 | Claude Code reads [../../AGENTS.md](../../AGENTS.md) only while no `CLAUDE.md`, `.claude/CLAUDE.md`, or `CLAUDE.local.md` exists in the working directory or above it. Since 2026-10-16, `pnpm check:docs` (and so pre-commit and the Stop hook) fails while any of them exists in the repository, and Claude Code deny rules block creating them with its edit tools. | Such a file in a directory **above** the repository still silently disables the entry point; nothing checks there. A contributor who legitimately wants a personal `CLAUDE.local.md` is blocked by the check. | That contributor should set **Project instructions** to `claude-md-and-agents-md` via `/config` (stored in user settings under `pluginConfigs`; ignored in project settings), then decide whether `forbidden` in `scripts/harness.json` should drop the file. If an ancestor file ever bites, add a warning for it to the SessionStart adapter. Revisit if the harness ever needs a committed `CLAUDE.md`. |
| TD-10 | `.claude/skills/*` are symlinks into `.agents/skills/`. Git preserves them, but a zip export, a Windows checkout without symlink support, or a copy made with `cp` without `-a` can turn them into broken or duplicated files. | Skills silently stop loading, or a second copy drifts from the canonical one. | Acceptable while the team is on macOS/Linux. If Windows joins, either enable `core.symlinks` there or move the canonical copies into `.claude/skills/` and update the docs map. |
| TD-11 | Neon's connection strings carry `sslmode=require`. `pg` 8.23 treats that as `verify-full` and warns on every server start that `pg` 9 will switch to libpq semantics, which skip certificate verification. | Server logs are noisy today. A `pg` 9 upgrade would silently weaken TLS verification. | Before upgrading `pg` to 9, set `sslmode=verify-full` explicitly. `neon env pull` rewrites these values, so normalize the URL in `src/server/db.ts` rather than editing `.env`. |
| TD-12 | Failed-login rows (`LoginAttempt`) and expired or revoked `ApiSession` rows are never pruned. Rows for emails that don't exist accumulate. | Unbounded but slow table growth. The throttle counts only the last 15 minutes, so correctness is unaffected. | Add a scheduled cleanup (a cron route or a Neon function) that deletes attempts older than the throttle window and sessions expired for more than a day. |
| TD-13 | The login throttle is per email, with no IP or client dimension. | Someone who knows an address can lock that account out of signing in for 15 minutes by submitting wrong passwords. | Add a per-IP limit and a short exponential delay, or move to a shared rate limiter, before real users depend on it. |
| TD-16 | Credential documents are stored as `bytea` in Postgres (owner decision, 2026-10-18), limited to 4 MB. | Every download and every save moves the whole file through the database, which costs egress and compute on Neon and grows the database. There is no virus scanning. | Move to private object storage (the original Vercel Blob proposal, or Neon object storage) before real use, keeping the same routes. Add scanning with it. |
| TD-17 | The admin and agency timesheet lists load every assignment and cancellation, with no paging, date range or agency filter (owner non-goal, 2026-10-18). | Each page's size and query cost grow with the data. | Add a date range and paging, or an admin agency filter, once the data grows or the owner asks. |
| TD-18 | `pnpm build` logs "Unhandled API error: Route /api/credentials/document needs to bail out of prerendering … used request.headers" twice: `errorResponse` (`src/server/errors.ts`) catches and logs Next's internal prerender bail-out. | Misleading error lines in local, CI and Vercel build logs. Behavior is correct: the route builds as dynamic, and production returns a live `401` (checked 2026-10-18). | Re-throw Next's internal errors before logging (check the bundled docs for `unstable_rethrow`), or call `await connection()` first, as `src/app/api/auth/me/route.ts` does. |
| TD-19 | CI and local test runs share the Neon `dev` branch (owner decision, 2026-10-18). CI runs queue among themselves, but a CI run and a local `pnpm test` or `pnpm test:e2e` can run at the same moment. | Either run can fail spuriously when it sees the other's rows on the shared accounts or seeded fixtures. | Rerun the failed run. If collisions become frequent, give each CI run a throwaway Neon branch, which needs a `NEON_API_KEY` secret and a change to the `NEON_BRANCH` guard. |
| TD-20 | Two feature components import another feature's component: `shifts/components/marketplace.tsx` uses the credentials banner and `timesheets/components/timesheet.tsx` uses shifts' `StatCard`. The separation of server code, contracts and actions (2026-10-19) left them in place. | Features are coupled, against the dependency rule in ARCHITECTURE.md §3. No server code is involved. | Move `StatCard` to `src/shared/ui/`, and pass the credentials banner into `marketplace` from the page, or share it through `shared/ui/`. |

TD-13 is the item most likely to cause real damage now that the app is public: the sample accounts' emails are published in the spec and the README, so anyone can lock one out of signing in for 15 minutes while a reviewer is using it.
