# Contextual commits

Read [AGENTS.md](../../../AGENTS.md), [docs/VERIFICATION.md](../../../docs/VERIFICATION.md), and the relevant active plan. Inspect `git status`, both staged and unstaged diffs, untracked files, and recent commit subjects. Establish exactly what was requested; preserve unrelated work and anything already staged. On the default branch, create a branch first unless asked to commit there.

**Plan the split before staging anything.** Group by independent intent or boundary — a toolchain pin, a test setup, documentation, a checker, hooks, one tool's adapter. Keep tests with the behavior they cover and `pnpm-lock.yaml` with the dependency change that moved it. Do not split by file type, and do not merge unrelated work just because it shares a directory. Write down each commit's subject and exact path set, and show that list before the first commit.

**Order by dependency.** A commit lands with or after whatever it imports, links to, or requires: a module before its importer, the paths a checker requires before the checker. From the commit that introduces a check onward, every snapshot must pass it.

**Split a shared file through the index, not the working tree.** When one file carries several contexts — `package.json` scripts and dependencies, `.gitignore` blocks, a test file covering two modules — write each intermediate version to a scratch directory outside the repository and stage it directly:

```sh
git update-index --add --cacheinfo 100644,"$(git hash-object -w <scratch>/package.c1.json)",package.json
```

Derive intermediates from the final file by removing the later contexts programmatically, never by retyping, and confirm that removing all of them reproduces `HEAD` exactly. The last commit touching the file stages the working-tree version, so the final tree matches the disk. A person can use `git add -p` instead; an agent without an interactive terminal cannot.

**Stage and inspect.** Stage only intended paths — never `git add -A` in a mixed tree. Before each commit, read `git diff --cached --stat`, the full staged diff, and `git diff --cached --check`; fix trivial whitespace such as a blank line at end of file in the working tree and re-stage it. Check modes with `git ls-files -s`: hooks `100755`, symlinks `120000`. Never stage `.env*`, `.next/`, `node_modules/`, `test-results/`, or `playwright-report/`.

The `nextjs-agent-rules` block at the top of `AGENTS.md` is regenerated by `next dev`. If it reappears as an uncommitted change, commit it with the work rather than reverting it.

**Verify snapshots, not only the working tree.** Git hooks inspect the working tree, so a passing hook does not prove a partial commit is sound. For a non-trivial split, check the staged snapshot before committing and each committed revision afterwards, in a scratch directory outside the repository:

```sh
git checkout-index -a --prefix=<scratch>/staged/   # the index, before committing
git archive <sha> | tar -x -C <scratch>/<sha>      # a commit, afterwards
```

Run the checks that apply there — `python3 scripts/check_harness.py` and the unit suites in `docs/VERIFICATION.md` — then delete the scratch copy. When a command deletes it, say in the request that the path is a temporary copy outside the repository. Snapshots have no `node_modules`; when their TypeScript files are identical to the working tree, the hook's lint and typecheck results carry over. Run the full verification `docs/VERIFICATION.md` requires on the final state. Do not bypass a failing hook with `--no-verify` unless asked, and report it if you do.

**Write the message.** Use `type(scope): imperative summary` with a Conventional Commits type (`feat`, `fix`, `docs`, `test`, `build`, `chore`, `refactor`, `perf`, `ci`); drop the scope when it adds nothing. Add a body explaining *why* when the reasoning or a tradeoff is not obvious from the diff, wrapped near 72 columns, and a `BREAKING CHANGE:` footer for incompatibility. Append any attribution trailer the user or tool requires. Pass multi-line messages with `git commit -F -` and a heredoc. After each commit, confirm its contents and the remaining status before continuing. Do not push or rewrite shared history unless asked.

Report a table of hashes and subjects, the verification actually run — per snapshot and final — and any requested work left uncommitted with the reason.
