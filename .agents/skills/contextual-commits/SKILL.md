# Contextual commits

Read [AGENTS.md](../../../AGENTS.md), [docs/VERIFICATION.md](../../../docs/VERIFICATION.md), and the relevant active plan. Inspect `git status`, both staged and unstaged diffs, untracked files, and recent commit subjects. Establish exactly what was requested; preserve unrelated work and anything already staged.

Group by independent intent or boundary. Keep tests with the behavior they cover and `pnpm-lock.yaml` with the dependency change that moved it. Do not split by file type, and do not merge unrelated work just because it shares a directory. For multiple commits, decide each subject and its exact path set before staging anything.

Stage only intended paths or hunks — avoid `git add -A` in a mixed tree. Inspect the full staged diff, a whitespace check, and `--stat` before committing. Never stage `.env*`, `.next/`, `node_modules/`, `test-results/`, or `playwright-report/`.

The `nextjs-agent-rules` block at the top of `AGENTS.md` is regenerated by `next dev`. If it reappears as an uncommitted change, commit it with the work rather than reverting it.

Run the verification `docs/VERIFICATION.md` requires for the final state, and focused checks for intermediate snapshots where it matters. Git hooks inspect the working tree, so they do not prove a partially staged commit is sound — inspect the snapshot, or check out the revision, when the split is non-trivial. Do not bypass a failing hook with `--no-verify` unless asked, and report it if you do.

Use `type(scope): imperative summary`; drop the scope when it adds nothing. Add a body when the reasoning or a tradeoff is not obvious from the diff, and a `BREAKING CHANGE:` footer for incompatibility. After each commit, confirm its contents and the remaining status before continuing. Do not push or rewrite shared history unless asked.

Report the hashes and subjects created, the verification actually run, and any requested work left uncommitted with the reason.
